# Taskovia C1 v1.2 implementation plan

**Goal:** Complete C1 using controlled accounting-data onboarding rather than runtime workbook upload.

## P2.1 — source model and controlled-import contracts

Define strict source/version/provenance/figure/review/import-manifest/import-run schemas, decimal-string boundaries, company scope, source-only audit, idempotency, and non-posting assertions. Test uncertain/unscoped data, manifest mismatch, repeated import, and no fake master-data creation.

## P2.2 — workbook-specific analysis and importer

For each explicitly supplied workbook family, inspect structure, produce a human-reviewable mapping manifest, implement only its focused adapter/import command, and test unsupported structure before mutation. Do not persist every cell or build generic ETL.

## P2.3 — database isolation and import verification

Add the reviewed forward migration and transaction-safe synthetic fixtures for tenant/company isolation, import identity, replay, provenance, immutable source history, and zero financial activation. Cloud application requires separate authorization.

## Later phases

P3 consumes imported P2 provenance for normalization/publication. P4 retains allocations/corrections/coverage. P5 retains reporting/source review but defers runtime upload/preview. P6 verifies controlled-import provenance, isolation, non-posting behavior, financial correctness, and reporting truthfulness.

## Constraints

No real-data import, Cloud mutation, production action, generic ETL, C2/C3 work, or runtime upload feature is implied by this plan.
