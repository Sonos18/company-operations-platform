# MATERIALS worker runtime

Build context comes only from two frozen Git refs. Run `./infra/instacloud/material-worker/prepare-context.sh` in this infrastructure worktree; it prints a fresh `/tmp/taskovia-runtime-context.*` directory for the authorized deploy. The script exports the runtime files from its current Git HEAD and `package.json` and `pnpm-lock.yaml` from materials `0118d57224b9a9f37b8f0a983a37db430768df88` and legacy DEV `ab2dcbd0abf5311b12f95d36b3120fd8aa097707`. Its Docker ignore file allows only the Dockerfile, two runtime scripts, and those four frozen manifests into the build. No source, Git data, `.insta`, credentials, or environment files enter the context. Remove the temporary context only after the deploy result is recorded.

The image extends the existing worker image by digest, preserving its Codex/AGY tools and Jev entrypoint. It pins pnpm 10.29.3. Each lock has its own `/opt/taskovia-runtime/profiles/<lock-sha256>/node_modules` and virtual store; the two installs share the image's pnpm content store. During image build only the root `nuxt prepare` postinstall is removed from a temporary manifest. Dependency lifecycle scripts are restricted to the three packages found in the frozen legacy graph: `esbuild`, `unrs-resolver`, and `vue-demi`. Each original manifest is restored byte for byte. Run Nuxt prepare in the actual source worktree after attachment. The container command validates tools and profiles, then sleeps; it starts no app, migration, or database job. The existing service's explicit start command may override image CMD, so the authorized deployment must select `sh /opt/taskovia-runtime/bin/start-worker.sh` or run its `--check` mode explicitly.

Source worktrees stay under `/data/taskovia` and direct children of `/data/remote-worktrees`. Generated `.nuxt`, `.output`, and a per-worktree `node_modules` facade live under `/tmp/taskovia-runtime/<path-sha256>`; only links are stored in the persistent worktree. The facade exposes pinned packages and keeps `node_modules/.cache` and `node_modules/.vite` writable for that worktree. The attach helper checks the worktree's lock and dependency manifest against an image profile before any writes. Script-only manifest differences are allowed with the same exact lock. It refuses existing real cache directories or unexpected links. In particular, `/data/taskovia/node_modules` is the existing 750 MiB real directory and two older worktrees link to it; an authorized migration must inspect and relocate those paths after the new image works. Boot does not remove or rewrite them.

After deployment and explicit migration, attach with `sh /opt/taskovia-runtime/bin/attach-runtime.sh /data/taskovia` or an approved direct child worktree. Then run `pnpm exec nuxt prepare` from the attached full source worktree. Check `pnpm exec supabase --version` (the frozen CLI is 2.114.0) without invoking a database command, followed by the authorized project checks such as unit tests, typecheck, lint, and build. No Cloud DEV or Production database action is part of this runtime.
